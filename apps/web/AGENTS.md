# apps/web — TanStack Start frontend

## Stack

- TanStack Start (SSR) + TanStack Router (file-based, `src/routes/`) + TanStack Query.
- Biome lints/formats (config at repo root); vitest for tests.
- `src/routeTree.gen.ts` is GENERATED by vite — never edit it.

## API access — the one rule

**Never hand-write fetch calls or API types.** Use the generated client
`@acme/api-client` (`useQuery(listUsersOptions())`, loader
`context.queryClient.ensureQueryData(...)`). If an endpoint is missing, add it to
`apps/api` and run `make client`.

## Environment

- `src/lib/env.ts` is the only place env vars are read: browser gets
  `VITE_API_BASE_URL` (inlined at build — **no secrets in VITE_\* vars**), SSR gets
  `API_BASE_URL` at runtime (in prod: docker-internal `http://api:8000`).
- Changing env vars ⇒ update `.env.example` + `docs/environments.md` in the same PR.

## Patterns

- Route = `createFileRoute('/path')({ loader, component })`; SSR prefetch in loaders;
  `useQuery` in components; query client is per-request (see `src/router.tsx`).
- Root document (`src/routes/__root.tsx`) owns `<html>`/`<head>` + QueryClientProvider.
- Styling is deliberately minimal — add Tailwind or CSS modules when the first real UI
  lands, and record the choice in `docs/decisions/`.
